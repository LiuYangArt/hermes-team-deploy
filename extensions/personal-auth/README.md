# 按说话的人授权和查询

普通成员可以在 Lark 对话里为自己授权，不需要管理员代办。看自己的 Lark 任务，以及 Meegle 的查询和修改，都使用当前发起人的授权。Lark 任务写入仍使用机器人身份。

## 使用

对机器人说“查看我的任务，需要授权时给我授权入口”。机器人通过 `personal_auth` 发起授权，返回链接、二维码和有效期。本人完成后回复“已授权”，机器人核对账号并继续查询。查看和退出登录也通过这个工具完成。

Lark 授权申请任务读取和工作邮箱读取权限，官方设备流程附加离线续期权限。Meegle 首次绑定前需要完成 Lark 授权，再核对两边的工作邮箱。邮箱缺失或不同会停止绑定，不能通过姓名猜测账号归属。Meegle 支持 `meegle.com` 和 `project.feishu.cn`。

## 身份边界

- 发起人来自当前 Lark 消息，不接受模型指定其他人的编号。
- Lark 用服务端返回的 open id 核对；Meegle 用当前登录账号的工作邮箱与已核实的 Lark 账号核对。
- 待完成授权单独保存。核对成功后才启用；错人扫码、过期和退出只清除本人的对应状态。
- 每个人的配置和加密令牌都分开保存。只分开配置文件不足以隔离官方 CLI 的令牌存储。
- 共享应用密钥、管理员名单和机器人身份继续由后台管理。模型不能通过直接登录命令或读写凭据文件绕过绑定。
- `status` 返回本机绑定状态；真实查询仍由官方工具验证令牌。退出清除机器人上的登录，平台服务端的授权由用户在平台授权管理页撤销。

## 保存与验证

已授权的查询通过单条直接 CLI 调用运行，扩展只绑定当前人的环境目录，不额外包装 `sh -c`。日期查询保持原样；这两类正常读取无需管理员批准，任意 shell 脚本仍接受原有安全检查。

状态在受保护运行目录 `personal-auth/<发起人>/`。`lark/` 同时保存配置和独立 `.data/` 令牌存储；`meegle-home/` 保存官方 Meegle 状态。设备码不返回模型，不写入 Git。授权二维码属于临时产物，完成、过期检查或退出时删除本地文件。已有但未核验的旧授权不直接启用，需要本人重新授权。

单元验证：`python3 -m unittest discover -s tests -p 'test_personal*.py' -v`。启动验证：`python3 -m unittest discover -s tests -p 'test_team_startup.py' -v`。本地证据在 `artifacts/issue-23/`。

云端验收必须包含普通成员发起授权、本人扫码、查询回读及第二人隔离。单元测试和授权链接生成成功不代表真人授权已通过。这里是扩展层的请求绑定，不声称已实现容器或操作系统级执行隔离。

## 查询结果整理

镜像提供 jq。先使用 CLI 字段选择（Meegle 的 `--select`）或服务端条件缩小结果；需要本地筛选、排序、分组计数时，直接使用 `jq '表达式' 本轮结果文件`。CLI 查询和本地整理分两次工具调用，不拼接 shell 管道，不为 JSON 整理生成 Python、Node 或 shell 脚本。先确认实际数据结构并取齐分页，才输出全量统计。

这是一条通用数据处理路径，不是命令白名单，也不绕过安全扫描。jq 调用仍经过原来的终端检查；管理员审批、本人授权和现有凭据边界保持不变。系统当前也不声称提供操作系统级多用户文件隔离。

### 容器重建与 Meegle 凭据

Meegle CLI 1.0.23 的凭据密钥派生依赖系统主机名和 USER。Compose 固定主机名为 `hermes-team-official`，授权和查询固定使用 `USER=hermes`，避免重建容器后已有凭据无法读取。首次从随机主机名切换时需要本人重新授权一次；不要把凭据文件存在当作在线授权有效。

## 定时任务

定时任务固定使用创建者授权，手动触发者和后续聊天参与者不会改变身份。身份从调度器内部任务编号对应的持久任务记录获取，不接受模型传入身份或从提示词解析身份。

创建入口继续是 `cronjob_manage`。扩展通过官方 `register_tool(override=True)` 接口包装该工具，启动配置明确启用 `plugins.entries.personal-auth.allow_tool_override`。创建时必须声明 `personal_services`（`lark`、`meegle` 或空列表），保存任务前在线核对创建者账号。缺授权先由本人完成 `personal_auth start/complete`，再创建。任务先以暂停状态落盘，授权要求写入后才启用；写入中断时保留暂停，不能产生未绑定的可运行任务。

后台仅允许查看授权状态；禁止发起扫码、完成授权、退出登录或使用未声明的服务。凭据仍存于创建者原来的个人目录，任务记录不复制令牌。令牌撤销后查询会失败，不换用其他人的授权。个人授权任务通过受管工具执行，不允许用绕过工具绑定的独立脚本执行。

拆开命令名，或用 shell、python、node 间接调用 Lark / Meegle 时，命令会被拒绝，并说明登录仍在。这种拒绝不能当成未授权，也不能要求用户重新扫码；应改成一条直接命令。直接命令才会带上创建者的登录。

更新、恢复和手动运行仍核验原创建者，权限管理仍由 lark-access 负责。改变个人授权服务范围需要重新创建任务；不允许仅改提示词偷偷扩大已声明范围。普通提醒可声明空列表。既有任务须由运维核实来源与授权后显式登记要求，不自动猜测并赋权。

回归命令：`python3 -m unittest discover -s tests -p 'test_personal*.py' -v`。上线同时运行 `test_team_startup.py`，验证配置、授权目录和其他任务保持不变。

## Meegle 建单免二次确认

用户明确要求建单后，机器人直接校验字段、创建并回读单号和链接。只讨论方案或索要草稿不算建单授权。目标有歧义或缺少必要信息时仍需询问。返回结果不确定时，先查询核实，避免重复创建。

运行配置使用 Hermes 官方 `command_allowlist`，仅添加以下两项。路径以容器内 `/opt/data` 为准；其他安装目录需对应调整。保留配置中已有条目。

```yaml
command_allowlist:
  - 'env HOME=/opt/data/personal-auth/*/meegle-home USER=hermes meegle workitem create *'
  - 'env HOME=/opt/data/personal-auth/*/meegle-home USER=hermes /usr/local/bin/meegle workitem create *'
```

这些条目只匹配个人授权扩展绑定账号后的单条建单命令。首次账号授权、退出后的重新登录以及 Meegle 服务端权限检查继续生效。更新、删除和其他命令不匹配；全局审批模式不变。复合 shell 命令仍由原有检查拒绝或审批。

2026-10-09 的真实建单记录显示，安全扫描把正文中的中文句号 `U+3002` 判断为易混淆字符，触发审批。上述配置为已授权建单设置固定例外，避免正文文本造成重复批准。白名单属于运行配置，需随配置备份保存，不写进公共镜像。

验证：`HERMES_CORE_PATH=/path/to/hermes-team python -m unittest discover -s tests -p 'test_meegle_create_approval.py' -v`。该测试只检查命令匹配和账号边界，不创建业务数据。云端运行验证及真实群聊结果记录在 Issue #35 和本地 `artifacts/issue-meegle-approval/`。
