# Lark 话题扩展

归属：多个 Lark 场景共用的话题参与。不包含单个任务的分类、翻译或派单规则。

它在官方飞书适配器之外做两件事：群里第一次 @ 机器人时，先定下一条稳定讨论，再让回答落进原生话题；之后同一话题里的消息继续用这条讨论。话题有了服务端编号之后，回答回复到这条话题自己的原消息，避免主群引用再开一个话题。还没有服务端话题、又没有可回复的原消息时，发送直接失败，不改发到群顶层。

最近一次 @ 机器人的人接着说，就当作对机器人说。他改去 @ 别人、而且没有 @ 机器人时，整条话题安静下来，只把话记下。一句话里同时 @ 机器人和别人，仍然是在叫机器人。安静之后，话题里任何人再 @ 机器人，才继续回答，并把刚才记下的话当作背景。别人在话题里说话、没有 @ 机器人，机器人不回复。

有人把机器人自己发出的群消息收成话题时，第一个开口的人就是当前对话对象，第一条也不用 @。这个人第一条就 @ 了别人、又没 @ 机器人，话题保持安静。同事的消息被收成话题时，机器人不主动接；查过一次开头是谁之后就记住，不再每次重查。任何还没记下来的话题里，只要有人 @ 机器人，就把这个人记成对话对象，下一句不用再 @。记下来之后仍用上面的规则。

停止、批准和确认只接受当前这件事的发起人。同一条话题里后来的请求排在后面，不打断正在做的事。

状态写在运行目录的 `lark-topics/topics.json`，不进 Git。当前机器人已经启用这个扩展，测试群里的自动开题、引用回归、失败不漏发和重启恢复已有回读。

批准卡绑定到具体请求及原卡消息。点击后先核对管理员、群聊、卡片和请求，再显示结算结果。过期或已在别处处理时，提示更新在原卡中，不向群主聊天另发消息；重复点击保留首次结果。旧卡不会批准后来排队的新命令。依赖镜像内的通用请求编号补丁，见 `docs/PATCHES.md`。专项验证：`python3.13 -m unittest discover -s tests -p 'test_lark_approval_adapter.py' -v`。

同一轮里的进度和最终回答共用一条消息。最终回答发出之后，迟到的进度不再改它。处理被取消或失败、而最终回答还没发出时，这条消息改成一句说明。一条消息写不下的回答，第一段留在原消息里，剩下的另发。附件没有读出来时，会告诉对方重新发或改用文字。

Issue #8 的并发修复将首发、编辑和结束处理放进每轮独立的锁；不同话题不共用锁。发送取消时先等待已发请求的回执，最多等待本次传输 30 秒；超时后封闭本轮，避免再次首发。平台或网络没有返回消息编号时，不能证明消息未发送，也不能保证自动清理已被平台接收的消息。

Lark 文本消息最多编辑 20 次，进度发送与直接编辑共用 18 次预算，预留最终回答和失败收尾。相同内容不重复编辑；超过预算的中间进度不再发出。流式段落边界不算整轮完成，结束时补齐最后一次已定稿预览。超长最终回答沿原话题继续分片，已成功的分片不会因后续失败而重复发送。

本机标准库验证：`python3.13 -m unittest discover -s tests -p 'test_lark_reply_adapter.py' -v`（并发、取消、编辑额度与段落边界）。完整运行记录与真实消息回读留在忽略的 `artifacts/issue-8/`；模拟测试不等于云端群聊端到端通过。
