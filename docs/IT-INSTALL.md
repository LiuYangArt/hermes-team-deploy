## 2026-10-11 普通成员 @ 无响应（#15）

根因是云端群聊接入只允许管理员。`auto_enroll=true` 位于接入检查之后，普通成员到不了自动登记。原消息正确 @ 了当前机器人；运行中的适配器复现 `group_policy_rejected`。此前管理员对话通过，不能证明普通成员入口可用。

团队群聊在受保护的 `bot.env` 设置 `FEISHU_GROUP_POLICY=open`，由 `lark-access` 登记成员并限制管理操作。管理员仍保存在 `data/lark-access/config.json`。`FEISHU_ALLOW_ALL_USERS` 保持空，已有接入名单保留。新增安装采用同一群策略；已有安装先备份，再按团队实际接入约定修改。

云端仅修改这一项并执行 `hermesctl recreate`，管理员与模型配置哈希保持不变。回读实际适配器，普通成员的显式 @ 已通过接入。该检查不发送或重放原业务请求。验证产物位于忽略目录 `artifacts/issue-15-regression/`。

`my bots` 真实请求已收到 ASTRA 的“接入正常 ACK151011”，并回读同话题的请求和回复编号。普通成员接入、自动登记、认可名单和管理权限拒绝，在云端实际代码与临时状态中验证通过。临时状态已清理。Eric 本人再次 @ 的真实回合尚未发生，#15 保持待验收。

排查同类问题时，先看 `bot.env` 的群策略，再检查 `lark-access` 的登记开关。管理员能对话不代表同事能对话；历史日志中的模型报错也不能替代具体消息的接入检查。
